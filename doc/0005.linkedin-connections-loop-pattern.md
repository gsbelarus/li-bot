# LinkedIn Connections Loop Pattern

This note describes the runtime pattern now supported by `rc` for stateful LinkedIn workflows such as:

- open a contact from the Connections list,
- inspect the latest post,
- react or comment based on post age,
- mark inactive contacts in the task log,
- return to the list and continue with the next contact until the counter is reached.

## Runtime primitives to use

- `set_runtime_value`
- `increment_runtime_value`
- `branch_if_runtime_value`
- `jump`
- `return_to_profile_source`
- `open_next_profile_candidate`
- `log_runtime_value`
- `inspect_linkedin_latest_post` with `params.outputKey`
- `select_linkedin_post_candidate`
- `generate_comment`
- `focus`
- `go_back`
- `log_processed_post`

## Recommended state keys

- `processedCount`: number of contacts already handled.
- `targetCount`: maximum number of contacts to process.
- `contactAssessment`: object returned by the built-in LinkedIn latest-post inspection step.
- `customContactAssessment`: optional object returned by a custom inspection step when the script needs a different schema.

Recommended `contactAssessment` shape:

```json
{
  "status": "inactive",
  "ageDays": 210,
  "hasPosts": false,
  "shouldReact": false,
  "shouldComment": false,
  "publishedAtText": "6 mo",
  "imageCount": 0,
  "commentText": ""
}
```

When a script mixes the built-in latest-post inspection with a custom inspection step, keep the custom payload under a different key such as `customContactAssessment` so branches and logs do not accidentally read the wrong shape.

## Authoring pattern

1. Initialize `processedCount` to `0` and `targetCount` to `5`.
2. Navigate to LinkedIn Connections.
3. Click the first profile card from the list page. This captures the source-page context automatically.
4. Open the profile posts/activity view.
5. Run an `inspect_linkedin_latest_post` step and set `params.outputKey="contactAssessment"`.
6. Or, when the workflow must choose the first eligible unprocessed post rather than only the latest visible post, run `select_linkedin_post_candidate` and set `params.outputKey="selectedPost"`.
6. Branch on `contactAssessment.status`.
7. If inactive, call `log_runtime_value` for `contactAssessment`.
8. If active, branch on `contactAssessment.shouldComment`.
9. Perform the reaction-only or reaction-plus-comment path.
10. Increment `processedCount`.
11. Branch on `processedCount < targetCount` using `branch_if_runtime_value`.
12. If more contacts remain, `return_to_profile_source`, `open_next_profile_candidate`, and `jump` back to the posts/activity processing step.

## Minimal control-flow sketch

```json
{
  "version": 1,
  "summary": "Process latest posts from the newest LinkedIn connections",
  "defaultDelayMs": 1000,
  "steps": [
    {
      "order": 1,
      "kind": "set_runtime_value",
      "instruction": "Initialize processed contact count",
      "delayAfterMs": 0,
      "timeoutMs": 10000,
      "target": null,
      "params": { "key": "processedCount", "value": 0 }
    },
    {
      "order": 2,
      "kind": "set_runtime_value",
      "instruction": "Set target contact count",
      "delayAfterMs": 0,
      "timeoutMs": 10000,
      "target": null,
      "params": { "key": "targetCount", "value": 5 }
    },
    {
      "order": 30,
      "kind": "inspect_linkedin_latest_post",
      "instruction": "Inspect the latest post and classify the contact",
      "delayAfterMs": 0,
      "timeoutMs": 15000,
      "target": null,
      "params": {
        "outputKey": "contactAssessment",
        "commentWithinDays": 14,
        "inactiveAfterDays": 180,
        "commentText": "Great post. Thanks for sharing."
      }
    },
    {
      "order": 40,
      "kind": "branch_if_runtime_value",
      "instruction": "If the contact is inactive, jump to inactive logging",
      "delayAfterMs": 0,
      "timeoutMs": 10000,
      "target": null,
      "params": {
        "key": "contactAssessment.status",
        "operator": "equals",
        "value": "inactive",
        "onMatch": "jump",
        "jumpToOrder": 70
      }
    },
    {
      "order": 70,
      "kind": "log_runtime_value",
      "instruction": "Log the inactive contact assessment",
      "delayAfterMs": 0,
      "timeoutMs": 10000,
      "target": null,
      "params": {
        "label": "inactive",
        "key": "contactAssessment"
      }
    },
    {
      "order": 80,
      "kind": "increment_runtime_value",
      "instruction": "Increment processed contact count",
      "delayAfterMs": 0,
      "timeoutMs": 10000,
      "target": null,
      "params": { "key": "processedCount", "amount": 1 }
    },
    {
      "order": 90,
      "kind": "branch_if_runtime_value",
      "instruction": "Loop while fewer than the target number of contacts were processed",
      "delayAfterMs": 0,
      "timeoutMs": 10000,
      "target": null,
      "params": {
        "key": "processedCount",
        "operator": "lt",
        "value": 5,
        "onMatch": "jump",
        "jumpToOrder": 100
      }
    },
    {
      "order": 100,
      "kind": "return_to_profile_source",
      "instruction": "Return to the saved connections list",
      "delayAfterMs": 0,
      "timeoutMs": 15000,
      "target": null,
      "params": {}
    },
    {
      "order": 110,
      "kind": "open_next_profile_candidate",
      "instruction": "Open the next contact from the same saved list",
      "delayAfterMs": 0,
      "timeoutMs": 15000,
      "target": null,
      "params": { "onMissing": "end_script" }
    },
    {
      "order": 120,
      "kind": "jump",
      "instruction": "Jump back to the post-inspection block",
      "delayAfterMs": 0,
      "timeoutMs": 10000,
      "target": null,
      "params": { "jumpToOrder": 30 }
    }
  ]
}
```

The first-class `inspect_linkedin_latest_post` step removes the need for a custom DOM expression just to classify post age and activity. The engine can now preserve state, branch on the returned assessment, jump back into a loop, return to the saved list page, open the next candidate, and persist structured inactive or outcome log entries.

For post-level workflows, the engine can also select the first eligible unprocessed post from the activity list, bind later actions to that same selected post with `params.useSelectedPost=true`, generate a relevant comment server-side, log the processed post URL, and return with `go_back` when the script must move from the posts list back to the profile page.
