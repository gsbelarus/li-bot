1. The task is to create a Remote Controller system, which is a NodeJS Express TypeScript server running on remote VPS. This server will manage Chrome instances and communicate with the Open Claw Bot. The Remote Controller will allow operators to control and monitor their VPS and Chrome instances remotely through a web interface, saving time and increasing efficiency by eliminating the need for manual logins and interactions with the VPS.
2. The source code for the Remote Controller is located in the `rc` folder of the repository. Init the project there using `pnpm`. Put the source code for the Remote Controller in the `src` folder inside `rc`. The entry point of the server should be `src/index.ts`.
3. The Remote Controller should use authentication via shared secret key. The secret key should be stored in an environment variable `REMOTE_CONTROLLER_SECRET_KEY`. The Remote Controller should validate the secret key for every incoming request and reject requests with an invalid or missing secret key with a 401 Unauthorized response.
4. Check that the secret key is stored per VPS, so each VPS can have its own secret key. This allows for better security and flexibility in managing multiple VPS. For that check the `Control Center Server` code. If there is no support for storing the secret key per VPS, implement it in the `Control Center Server` and update the database schema accordingly. Then update the docs in the doc\0002.remote-vps-registry.md to reflect the changes made to the `Control Center Server` for storing the secret key per VPS.
5. The Remote Controller should have an API endpoint to receive commands from the Control Center Server. The endpoint should be `POST /api/commands`. The request body should contain the command to be executed and any necessary parameters. The Remote Controller should validate the command and parameters, execute the command using the Open Claw Bot, and return the result of the command execution in the response.
6. The first command to implement is the `executeScript` command, which will receive a script in the request body and execute it using the Open Claw Bot. 
    1. The script should be in a structured JSON format that defines the steps to be executed. For the structure of the script, you can refer to the `ScriptInstructions` type defined in `ccs/lib/scripts-shared.ts`. 
    2. The Remote Controller should parse the script, validate the steps, and execute them in order using the Open Claw Bot. The Remote Controller should handle any errors that occur during the execution of the script and return appropriate error messages in the response.
    3. For the reference how to call the Open Claw Bot from the Remote Controller, you can refer to the existing script in the `script\script_1.js` file.
    4. The Remote Controller should return a task ID in the response when a script execution is initiated. This task ID can be used to track the status of the script execution and retrieve the results once the execution is completed.
7. The Remote Controller should have an API endpoint to retrieve the status of a script execution. The endpoint should be `GET /api/commands/:taskId/status`. The Remote Controller should return the current status of the script execution (e.g., pending, in progress, completed, failed) and any relevant information (e.g., error messages, results) in the response.
8. The Remote Controller should have an API endpoint to retrieve the results of a completed script execution. The endpoint should be `GET /api/commands/:taskId/results`. The Remote Controller should return the results of the script execution in the response. If the script execution is not yet completed, the Remote Controller should return an appropriate message indicating that the results are not yet available.
9. The Remote Controller should have proper logging and error handling mechanisms in place to ensure that any issues can be easily identified and resolved. Logs should include information about incoming requests, executed commands, and any errors that occur during the execution of commands.
10. The Remote Controller should maintain an internal queue of commands to be executed. This will allow the Remote Controller to prevent simultaneous execution of multiple commands that may interfere with each other. The Remote Controller should process the command queue sequentially, ensuring that each command is executed only after the previous command has completed. This will help to maintain the stability and reliability of the system when executing scripts on the remote VPS.
